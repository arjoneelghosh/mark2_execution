# Final Pre-Schema Plan

## What Currently Works Well

- Real routing and reusable page-shell architecture are in place and stable.
- Tier 2 behavior is functional and no longer decorative.
- Homepage visual quality is materially stronger after the design recovery pass.
- The large homepage ring and compact inner-page ring/control already share a common visual language.
- The assistant remains separate from the ring and the app is still clearly dummy-first.

## What Still Feels Visually Weak

- Compact inner-page navigation is still slightly cramped on smaller screens and could communicate active state more clearly.
- Inner pages still retain some generic app-shell rhythm instead of fully matching the premium homepage feel.
- Typography is improved but still slightly too “system UI” in some headers, pills, and card metadata.
- Project imagery still relies on remote placeholder URLs, which weakens review stability and visual control.
- Ask route messaging is functional but not yet fully intentional in how it frames the docked assistant relationship.

## What Will Be Improved In This Pass

- Compact nav spacing, hit areas, responsiveness, and active-page clarity.
- Shared shell and page composition rhythm for Work / Profile / Experience / Lab / Connect / Ask.
- Typography hierarchy, section spacing, pill rhythm, and card presentation.
- Local dummy project preview assets under a controlled project directory, with project data updated to use them.
- Background atmosphere refinement, including evaluating a very subtle rare streak layer only if it improves the calm cinematic feel.
- Clearer Ask-route framing around the separate docked assistant.

## What Is Explicitly Deferred Until After Schema / Data Planning

- Real portfolio content.
- Final production schema and data model decisions.
- Production AI, RAG, orchestration, or backend logic.
- Particle face / initials / full-name morph effects.
- Large Tier 2 URL-state refactors unless a change is extremely small and safe.
